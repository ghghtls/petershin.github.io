1. TravelMuse - AI 기반 여행 일정 추천 앱

📅 프로젝트 기간: 2025.05.29 ~ 2025.07.07

🎯 목표: 성향 테스트 기반의 AI 맞춤 여행 추천 앱 개발 및 UX 개선

📲 iOS 배포 링크: App Store에서 TravelMuse 보기

🔗 GitHub: github.com/jinsung99123/travel_muse_app

🛠 주요 기능

  • AI 성향 테스트: 여행 스타일(자연/도시/문화 등) 질문 기반으로 사용자 성향 분석, 결과를 Gemini 프롬프트에 반영
  • Gemini 기반 여행지 자동 추천: 성향 결과 + 지역 조건을 프롬프트로 구성해 AI가 맞춤 여행지 리스트 생성
  • 지도 기반 루트 시각화: Kakao/Google Maps API로 추천 장소를 지도 위에 마커 표시 및 경로 연결
  • 일정 커스터마이징: 캘린더 기반 날짜 선택 후 장소별 방문 시간 조정, 드래그 순서 변경
  • 홈화면 추천 피드: 현재 위치 기준 거리순 정렬, 태그 필터링, 키워드 검색 지원
  • 커뮤니티: 여행 후기 게시글 작성/수정/삭제, 이미지 첨부, 댓글 및 좋아요 기능
  • 마이페이지: 스크랩한 장소 목록, 작성 게시글 관리, 계정 설정

💡 기술 스택

  • Flutter 3.32 / Dart 3.8
  • Riverpod (MVVM)
  • Firebase Auth
  • Firestore
  • Firebase Storage
  • Cloud Functions
  • Gemini API
  • Kakao Maps API
  • Google Maps API
  • image_picker
  • flutter_image_compress
  • table_calendar

👨‍💻 본인 역할

  • AI 성향 테스트 구현
    여행 스타일 분류 질문지 설계 및 단계별 UI 흐름 구현. 각 응답값을 가중치 기반으로 집계하여 성향 태그(자연·문화·액티비티 등)로 변환하는 로직 작성. 결과 화면에서 Gemini 추천 화면으로 자연스럽게 연결되는 플로우 설계.
  • AI 추천받기 기능 로직 처리 및 UI 연결
    성향 태그 + 선택 지역을 구조화된 프롬프트로 조합해 Gemini API 호출. 응답 JSON을 파싱하여 Place 모델 리스트로 변환 후 지도 및 일정 화면에 바인딩. 로딩·오류 상태를 Riverpod Provider로 관리하며 UX 처리.
  • 커뮤니티 글 작성 · 수정 · 삭제 기능 개발
    Firestore + Firebase Storage 연동으로 텍스트 및 다중 이미지 게시글 CRUD 구현. 수정 시 기존 이미지 유지/교체 로직 처리, 삭제 시 Storage 파일도 함께 정리. 게시글 작성 폼 유효성 검사 및 제출 상태 관리.
  • 홈화면 UI / 거리순 정렬 / 검색 기능 구현
    Geolocator로 현재 위치 좌표를 획득하고 Haversine 공식 기반 거리 계산 후 장소 리스트를 거리순 정렬. 키워드 검색은 디바운싱 처리 적용. 태그 필터와 검색이 동시에 동작하도록 Riverpod 파생 Provider로 상태 합성.

2. ShareLingo - 글로벌 언어교류 SNS 앱

📅 프로젝트 기간: 2025.05 ~ 2025.05

🎯 목표: 글로벌 유저 간 실시간 언어 교류와 게시글 기반 학습 시스템 구축

🔗 배포 링크: 구글플레이에서 ShareLingo 보기

🔗 GitHub: github.com/zero-to-one-flutter/flutter-share-lingo

🛠 주요 기능

  • 게시글 작성 · 수정 · 삭제: 텍스트 + 다중 이미지 업로드, 언어/카테고리 태그 선택, 게시글 편집 및 삭제
  • YOLO 기반 이미지 안전성 필터링: YOLOv8 + TFLite 온디바이스 추론으로 인물 사진 업로드를 실시간 차단
  • 투표 기능: 게시글 내 투표 항목 생성, Firestore 트랜잭션 기반 실시간 투표 집계 및 결과 시각화
  • 좋아요 기능: 낙관적 UI 업데이트로 즉각적인 반응, Firestore 원자적 증감 처리
  • 피드 및 탐색: 언어·지역(읍면동 단위) 기반 피드 필터링, 주변 탭 / 팔로워 탭 분리
  • 댓글 · 신고: 댓글 작성/수정/삭제, 부적절 게시글 신고 기능
  • 무한 스크롤: Pull-to-Refresh + Firestore 커서 기반 페이지네이션

💡 기술 스택

  • Flutter + Riverpod
  • Clean Architecture
  • Firebase Auth
  • Firestore
  • Firebase Storage
  • Cloud Functions
  • Crashlytics
  • YOLOv8 + TFLite
  • Geolocator
  • VWorld API
  • GitHub Actions CI/CD
  • cached_network_image

👨‍💻 본인 역할

  • 게시글 작성 · 수정 · 삭제 기능 전체 구현
    Firestore 문서 + Firebase Storage 이미지를 함께 처리하는 CRUD 흐름 설계. 게시글 작성 시 이미지 압축 후 Storage 업로드, URL을 Firestore 문서에 저장. 수정 시 교체된 이미지만 새로 업로드하고 제거된 이미지는 Storage에서 삭제. 삭제 시 Storage 파일과 Firestore 문서를 순서대로 정리.
  • YOLO 이미지 필터링 연동
    TFLite 모델을 앱 초기화 시 비동기로 미리 로드하여 이미지 선택 즉시 추론 가능하도록 처리. 선택된 이미지를 모델 입력 사이즈로 리사이즈·정규화 후 추론 결과에서 'person' 클래스 탐지 시 업로드를 차단하고 사용자에게 안내 메시지 표시.
  • 태그 · 투표 기능 연동
    게시글 작성 폼에 태그 멀티셀렉트 UI 추가. 투표는 항목 최대 4개, 중복 투표 방지를 위해 Firestore 트랜잭션으로 투표 수 원자적 증감. 결과 화면에서 항목별 비율을 실시간으로 렌더링.
  • 좋아요 기능 구현
    탭 즉시 로컬 상태를 낙관적으로 업데이트한 뒤 Firestore FieldValue.increment로 서버에 반영. 빠른 연속 탭 방지를 위해 요청 완료 전까지 버튼 비활성화 처리.

3. PeopleJob - 취업 플랫폼 풀스택 리뉴얼

🎯 목표: 2019년 Java 레거시 기반 취업 플랫폼을 Spring Boot 3 + Flutter로 완전 재설계. 서버와 앱을 분리하고 JWT 인증 기반 REST API 구조로 전환

🔗 GitHub: Backend  |  Frontend

🛠 주요 기능

  • 회원 시스템: 구직자/기업 역할 분리, JWT 인증, 이메일 인증, 비밀번호 재설정
  • 채용공고: DRAFT → PUBLISHED → EXPIRED 상태 관리, 카테고리·지역 필터, 키워드 검색, 스크랩
  • 이력서: 구직자 이력서 CRUD (Quill 리치텍스트 편집기), 기업 이력서 검색
  • 지원 관리: 이력서 선택 후 지원, 기업의 지원자 목록 및 상태 관리
  • 광고 결제: 채용공고 상단 노출 광고 3단계 상품 선택 → 일정 선택 → 결제 흐름
  • 커뮤니티: 자유게시판 CRUD, 공지사항, 1:1 문의
  • 마이페이지: 지원 현황, 스크랩 목록, 작성 공고 관리, 통계
  • 관리자 패널: 회원·공고·지원자 관리, Excel 내보내기, FAQ·팝업 관리
  • 알림: Spring ApplicationEvent 기반 실시간 알림, 읽음 처리

💡 기술 스택

  • Spring Boot 3.4.4
  • Java 17
  • Spring Security + JWT
  • JPA + MyBatis
  • MySQL 8
  • Redis
  • SpringDoc Swagger
  • k6 부하 테스트
  • Flutter 3.7+
  • Riverpod
  • Dio
  • flutter_quill
  • go_router
  • AWS EC2 + RDS
  • Docker
  • GitHub Actions

👨‍💻 본인 역할 (풀스택)

  • 백엔드 REST API 설계 및 구현
    19개 컨트롤러 전 도메인(회원·공고·이력서·지원·게시판·결제·관리자·알림·파일 등) API 직접 설계 및 구현. OncePerRequestFilter 기반 JWT 인증 필터 커스텀 구현. Spring Security RBAC(ROLE_USER / ROLE_COMPANY / ROLE_ADMIN) 엔드포인트별 접근 제어 구성. @Cacheable / @CacheEvict 기반 Redis 캐시 전략(publishedJobs 10분 TTL), 마감 공고 자동 EXPIRED 처리 스케줄러, Spring ApplicationEvent 기반 실시간 알림 설계.
  • Flutter 앱 UI 및 상태 관리 구현
    go_router 기반 40+ 화면 Named 라우팅 구성 및 역할별 UI 분기(구직자/기업/관리자). Dio 인터셉터로 JWT 자동 주입 및 401 시 토큰 만료 처리. Riverpod StateNotifierProvider·FutureProvider로 채용공고·이력서·지원 상태 분리 관리. flutter_quill 기반 이력서 리치텍스트 편집기, FlutterSecureStorage 토큰 저장 구현.
  • 채용공고 상태 흐름 및 광고 결제 구현
    DRAFT → PUBLISHED → EXPIRED 6단계 상태 전환 API 및 Flutter UI 연결. 5단계 광고 결제 플로우(효과 안내 → 공고 선택 → 상품 선택 → 기간 선택 → 영수증) 화면 구현. Apache POI 기반 Excel 내보내기, 관리자 대시보드 회원·공고·지원자 일괄 관리 기능 구현.

🏗 시스템 아키텍처

  • 전체 흐름: Flutter(Dio + JWT Interceptor) → AWS EC2 (Spring Boot 3.4.4 · Port 5000) → Spring Security JWT Filter → RBAC(USER / COMPANY / ADMIN) → Redis Cache(10분 TTL) / MySQL 8(HikariCP 50 conn)
  • 인증 레이어: OncePerRequestFilter 기반 JWT 검증 → SecurityContext 주입 → 역할별 엔드포인트 분기 (구직자 / 기업 / 관리자)
  • 캐시 전략: 채용공고 목록(publishedJobs) Redis 캐시 10분 TTL. 공고 생성·수정·삭제·상태변경 시 @CacheEvict(allEntries=true)로 즉시 무효화 → 정합성 100% 보장
  • 스케줄러: 마감일 경과 공고 자동 EXPIRED 처리, 만료 토큰 일괄 정리(매일 02:00), Redis 연결 상태 헬스체크(10분 주기)
  • 모니터링: Spring Actuator + Micrometer Prometheus, k6 부하 테스트(100 VU 기준 HikariCP 50 connection pool 설정)

🧩 현재 상태

  • 백엔드 REST API 전 도메인 구현 완료 — 19개 컨트롤러, JWT 인증·Redis 캐시(10분 TTL)·스케줄러 포함, GitHub Actions CI 파이프라인 구축 완료
  • Flutter 앱 공고·이력서·마이페이지·지원 흐름 구현 완료 (40+ 화면 라우팅 구성), 결제·관리자 패널 고도화 진행 중
  • 결제 흐름 UI 5단계(효과 안내 → 공고 선택 → 상품 선택 → 기간 선택 → 영수증) 완성 — 실 PG 연동은 인프라 비용 관계로 모의 결제 흐름으로 대체 구현
  • AWS EC2 + RDS 인프라 아키텍처 설계 완료, Docker 기반 CD 파이프라인 고도화 진행 중

4. 매출 데이터 분석 대시보드 — Tableau

📅 진행 기간: 스파르타코딩클럽 데이터분석 재직자 과정 수료 프로젝트

🎯 목표: 스파르타코딩클럽에서 제공한 매출 데이터를 기반으로 지역·카테고리별 판매 현황을 시각화하고, 수익성 개선을 위한 인사이트를 도출하는 대시보드 구성

🛠 사용 도구: Tableau Desktop, Excel(데이터 전처리)

📊 분석 내용 및 대시보드

① 기초 모니터링 대시보드

핵심 KPI(총 매출·수익·주문 수·할인율)를 한눈에 파악할 수 있는 요약 뷰. 권역별 매출 합계를 맵 차트로 표현해 매출 집중 지역과 저성과 지역을 직관적으로 구분했습니다.

② 월간 지표 비교 대시보드

월별·분기별 매출 추이를 라인 차트로 시각화하여 계절성 패턴과 성장 구간을 파악했습니다. 전월 대비 증감률을 함께 표시해 이상 구간을 빠르게 탐지할 수 있도록 구성했습니다.

③ 상품 상세 대시보드

카테고리·서브카테고리 단위의 매출과 수익을 바 차트로 비교해 고수익 상품군과 손실 상품군을 분리했습니다. 할인율과 수익의 산점도를 추가해 할인율이 높을수록 수익이 감소하는 역상관 관계를 시각적으로 제시했습니다.

💡 주요 인사이트

  • 특정 카테고리에서 높은 매출에도 불구하고 할인율 과다로 수익이 마이너스(-) 구간 존재
  • 지역별 매출 편차가 크며, 일부 저성과 권역에 대한 영업 전략 재검토 필요성 도출
  • 월별 트렌드 분석으로 특정 분기에 매출이 집중되는 계절성 패턴 확인

👨‍💻 본인 역할

  • 데이터 전처리 및 구조 파악
    제공된 원시 데이터를 Excel에서 확인하고 날짜 형식 정리, 빈 값 처리 등 기본 전처리 후 Tableau에 연결.
  • 시각화 설계 및 대시보드 구성
    분석 목적에 맞게 차트 유형(맵·바·라인·산점도) 선택. 각 뷰를 독립적으로 제작 후 대시보드 캔버스에 배치, 공통 필터를 연결해 인터랙티브 탐색 가능하도록 구성.
  • 인사이트 도출 및 발표
    수치 데이터를 비즈니스 맥락으로 해석하여 개선 방향 3가지를 도출하고 발표 자료로 정리.

5. 코드명인 (인턴) — 중고 자동차 부품 거래 앱

🏢 소속: 코드명인 · 인턴

🎯 목표: 위탁자 · 판매자 · 소비자 3자 거래 구조 기반의 중고 자동차 부품 거래 모바일 플랫폼 개발. 실제 서비스 운영을 전제로 백엔드와 Flutter 앱의 통합 개발 담당.

🗺️ TravelMuse

1. Gemini API 응답 JSON 파싱 오류

문제: Gemini API에서 여행지 리스트를 JSON으로 받도록 프롬프트를 작성했으나, 실제 응답이 마크다운 코드블록(```json ... ```)으로 감싸지거나 중간에 설명 문장이 섞여 들어오는 경우가 있어 jsonDecode()가 FormatException을 던지며 앱이 크래시됐습니다.

해결: 정규식으로 응답 문자열에서 JSON 블록만 추출하는 전처리 함수를 작성했습니다. 추출된 문자열을 파싱한 뒤 예외가 발생할 경우 재시도 로직(최대 2회)을 추가하고, 그래도 실패하면 사용자에게 토스트 메시지를 보여주는 방식으로 안정성을 확보했습니다.

2. Kakao 장소 검색 API 과호출 (HTTP 429)

문제: Gemini가 추천한 10~15개 장소명을 Kakao 키워드 검색 API에 동시에 Future.wait()로 병렬 호출하자 HTTP 429 Too Many Requests 오류가 연속 발생했습니다.

해결: 병렬 호출을 순차 처리(for + await)로 전환하고 호출 사이에 짧은 지연(Future.delayed)을 삽입했습니다. 콜백 함수 반환 타입도 Future<void>로 명시해 중복 호출을 차단했습니다.

결과: API 429 오류 발생률 100% → 0% 로 해소. 10~15개 장소 좌표 조회 성공률 완전 회복 및 추천 플로우 안정화.

3. 성향 테스트 상태가 뒤로가기 시 초기화되는 문제

문제: 여러 단계로 이루어진 성향 테스트 도중 사용자가 이전 화면으로 돌아가면 Riverpod StateProvider가 dispose되면서 선택한 답변이 전부 초기화됐습니다.

해결: 테스트 진행 상태를 관리하는 Provider를 autoDispose 없이 전역 스코프로 선언하고, 테스트 완료 후 결과 화면 진입 시점에 명시적으로 ref.invalidate()를 호출해 초기화했습니다. 이를 통해 중간 이탈 후 복귀해도 답변이 유지되도록 개선했습니다.

4. 커뮤니티 이미지 수정 시 Storage에 파일이 계속 쌓이는 문제

문제: 게시글을 수정할 때 이미지를 새 것으로 바꾸면, 기존 이미지가 Firebase Storage에서 삭제되지 않고 그대로 남았습니다. 수정이 반복될수록 쓸모없는 파일이 계속 쌓여 Storage 용량을 낭비하는 문제였습니다.

해결: 수정 화면을 열 때 기존 이미지 URL 목록을 저장해두고, 저장 버튼을 눌렀을 때 새로 올린 이미지 URL과 비교했습니다. 비교 결과 사라진 이미지는 Storage에서도 직접 삭제하는 코드를 추가했고, Firestore 문서 저장과 Storage 파일 삭제를 순서대로 처리해 DB와 파일이 항상 일치하도록 했습니다.

5. 거리순 정렬 시 위치 권한 미처리로 앱 강제 종료

문제: 홈화면의 거리순 정렬 기능에서 Geolocator로 현재 위치를 요청할 때, 위치 권한이 거부된 상태에서 예외 처리 없이 좌표를 사용하려다 Null 참조 오류로 앱이 종료됐습니다.

해결: Geolocator.checkPermission()으로 권한 상태를 먼저 확인하고, 거부 상태라면 권한 요청 다이얼로그를 띄우는 단계를 추가했습니다. 권한이 영구 거부된 경우에는 거리순 정렬 대신 기본 정렬을 유지하고, 안내 토스트 메시지를 노출하는 방식으로 안전하게 처리했습니다.

6. 검색 입력 시 Firestore 과다 호출 문제

문제: 홈화면 검색 기능에서 사용자가 한 글자 입력할 때마다 Firestore 쿼리가 즉시 실행되어, 짧은 시간 안에 수십 번의 읽기 요청이 발생해 비용이 낭비되고 UI가 깜빡였습니다.

해결: Timer를 이용해 300ms 디바운싱을 적용하여 마지막 입력 후 일정 시간이 지난 뒤에만 쿼리가 실행되도록 했습니다. 또한 Riverpod의 파생 Provider를 활용해 검색어 상태와 태그 필터 상태를 합성함으로써 두 조건이 동시에 반영된 결과를 효율적으로 제공했습니다.

결과: 검색 입력 중 발생하는 Firestore 읽기 API 호출 횟수 약 75% 감소 (글자 입력마다 → 입력 완료 후 1회), UI 깜빡임 현상 완전 해결.

Firestore 저장 또는 이미지 업로드 후 Navigator.pop(context)를 사용할 때, Flutter의 경고 "Do not use BuildContext across async gaps"이 발생했습니다. 이를 해결하기 위해 if (context.mounted) 조건을 추가하여 안정성을 확보했습니다.

2. YOLO TFLite 모델 로딩 지연으로 첫 이미지 필터링 누락

문제: 앱 실행 후 처음 이미지를 선택할 때 TFLite 모델이 아직 초기화되지 않은 상태에서 이미지 추론이 실행되어, 인물 사진이 필터링되지 않고 그대로 업로드되는 경우가 있었습니다.

해결: 모델 로딩을 앱 시작 시점(main())에 비동기로 미리 실행하고, 로딩 완료 여부를 상태값으로 관리했습니다. 이미지 선택 버튼을 탭했을 때 모델이 아직 준비 중이라면 로딩 인디케이터를 보여주고 준비 완료 후 이미지 선택 화면으로 이동하도록 흐름을 수정했습니다.

결과: 첫 이미지 선택 시 필터링 누락 건수 0건으로 완전 차단. 모델 초기화 완료 보장으로 인물 사진 업로드 차단 로직 100% 동작.

3. 투표 동시 참여 시 카운트 덮어쓰기 문제

문제: 여러 사용자가 거의 동시에 투표하면 Firestore 투표 카운트가 마지막 쓰기 값으로 덮어써져 중간 투표가 사라지는 경우가 발생했습니다.

해결: 투표 항목 카운트 업데이트를 FieldValue.increment(1)을 사용하는 Firestore 트랜잭션으로 전환해 원자적으로 처리했습니다. 중복 투표 방지를 위해 userId를 투표자 목록 필드에 기록하고 이미 존재하면 요청을 차단하는 로직도 함께 추가했습니다.

4. 좋아요 빠른 연속 탭 시 카운트 오류

문제: 사용자가 좋아요 버튼을 빠르게 여러 번 탭하면 낙관적 업데이트와 실제 Firestore 응답이 뒤엉켜 카운트가 음수가 되거나 2 이상 증가하는 오류가 발생했습니다.

해결: 좋아요 요청이 진행 중인 동안에는 버튼을 비활성화하는 플래그를 Riverpod 상태에 추가했습니다. 첫 번째 요청 완료 후에만 다음 탭을 처리하도록 제어하여 중복 호출을 방지하고 UI 카운트와 서버 값이 항상 일치하도록 했습니다.

1. Dio 인터셉터에서 JWT 만료 시 무한 재시도 루프

문제: Flutter Dio 인터셉터에서 401 응답을 받으면 토큰을 갱신 후 요청을 재시도하도록 구현했는데, 리프레시 토큰도 만료된 경우 갱신 API가 또 401을 반환하면서 인터셉터가 무한으로 재시도하는 루프에 빠졌습니다.

해결: 재시도 여부를 나타내는 플래그를 요청 옵션(extra)에 담아, 이미 재시도한 요청이 다시 401을 받으면 더 이상 재시도하지 않고 즉시 로그아웃 처리하도록 했습니다. 리프레시 토큰 만료 시에는 flutter_secure_storage에 저장된 토큰을 삭제하고 로그인 화면으로 리다이렉트했습니다.

2. Spring Security CORS 설정 충돌로 Flutter 앱 API 호출 실패

문제: Flutter 웹 빌드에서 API를 호출하면 CORS 오류가 발생했습니다. 컨트롤러에 @CrossOrigin을 붙이면 일부 요청은 통과했지만 JWT가 필요한 엔드포인트에서는 여전히 차단됐습니다.

해결: @CrossOrigin과 SecurityConfig의 CORS 설정이 중복 적용되어 충돌하는 것이 원인이었습니다. 컨트롤러의 @CrossOrigin을 모두 제거하고 SecurityConfig에서 CorsConfigurationSource 빈을 하나로 통합해 허용 오리진·메서드·헤더를 일괄 관리했습니다.

3. 채용공고 Redis 캐시 갱신 타이밍 문제

문제: 채용공고를 수정하거나 상태를 변경한 직후에도 목록 API가 이전 데이터를 계속 반환했습니다. Redis에 캐시된 응답이 남아 있어서 실제 변경 내용이 바로 반영되지 않는 문제였습니다.

해결: 공고 생성·수정·삭제·상태 변경·만료 처리가 일어나는 서비스 메서드에 @CacheEvict(value = "publishedJobs", allEntries = true)를 추가했습니다. 이를 통해 데이터 변경 즉시 캐시가 무효화되고 다음 요청부터 DB에서 최신 데이터를 조회해 반환하도록 했습니다.

결과: 공고 변경 후 목록 API 정합성 100% 보장. Redis 캐시(10분 TTL) 적중 시 DB I/O 완전 우회, 변경 즉시 최신 데이터 반영 확인.

4. Flutter Riverpod 이력서 폼 상태 누적 문제

문제: 이력서 등록 화면에서 값을 입력한 뒤 뒤로가기로 나갔다가 다시 진입하면, 이전에 입력한 내용이 폼에 그대로 남아 있었습니다. 각 입력 필드를 개별 StateProvider로 관리하다 보니 화면을 떠나도 상태가 초기화되지 않았습니다.

해결: 이력서 폼 관련 Provider를 autoDispose 수식어가 붙은 Provider로 교체하여 화면이 종료될 때 자동으로 상태가 초기화되도록 했습니다. 수정 화면처럼 기존 데이터를 불러와야 하는 경우에는 ref.onDispose로 명시적 초기화 시점을 제어했습니다.
