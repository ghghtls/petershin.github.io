🛠 핵심 제품 기능 (PRD 범위)

  • 유저 성향 데이터 파이프라인: 5가지 스타일 질문 응답 데이터를 가중치 분석 알고리즘으로 처리, 사용자 태그(자연/문화 등)로 구조화
  • LLM 기반 자동 추천 엔진 기획: 성향 태그 + 선택 지역 조건을 프롬프트 템플릿으로 합성하여 개인화된 맞춤 일정 생성
  • 지도 기반 루트 시각화 UX: 추천된 장소의 공간 데이터를 지도 위 마커 및 동선으로 시각화하여 동선 효율성 검증 지원
  • 인터렉티브 일정 커스터마이징: 캘린더 연동, 방문 시간 배분, 드래그 앤 드롭 방식을 적용한 일정 편집 플로우 설계
  • 위치 기반 로컬 피드: 유저 위치 데이터 기반 거리순 정렬, 태그 필터링, 실시간 검색 기능 구축
  • 커뮤니티 & 마이페이지: 정성적 후기 공유(게시글/이미지/댓글) 및 스크랩 데이터 기반 개인화보관함 기획

  • 유저 성향 분석 알고리즘 및 온보딩 UX 기획
    성향 분류 질문지 및 가중치 집계 로직 설계. 답변 이탈 시 기존 입력값이 보존되는 세션 유지 정책을 수립하여 중도 이탈률 최소화.
  • AI 프롬프트 엔지니어링 & Fallback 정책 수립
    Gemini Pro 연동 시 LLM 응답의 비정형 텍스트 출력을 방지하기 위한 JSON Schema 명세 작성. AI 파싱 실패 시 재시도 및 유저 안내 토스트 띄움 처리로 서비스 연속성 보장.
  • 외부 API 비용 및 성능 최적화 정책 기획
    장소 검색 API 동시 호출로 인한 서드파티 제한 오류를 방지하기 위해 순차 제어 로직 명세. 검색어 입력 시 300ms 디바운스 정책을 적용하여 불필요한 API 호출 건수를 약 75% 절감.
  • 위치 데이터 기반 정렬 및 예외 처리 UX 명세
    Geolocator 기반 위치 권한 거부 유저를 위한 Fallback 정렬(기본 인기순) 가이드라인을 정의해 앱 튕김 현상을 0건으로 제어.

  • 데이터 정합성을 고려한 인터랙션 정책 기획
    다수 유저의 동시에 발생하는 투표/좋아요 데이터 오차를 방지하기 위해 원자적 카운팅(Transaction) 요구사항 명세. 중복 투표 차단 알고리즘 설계.
  • 미디어 데이터 라이프사이클 관리 명세
    게시글 수정/삭제 시 기존 이미지와 변경 이미지를 비교 검증하여 사용되지 않는 고아 파일(Orphan Files)을 자동 삭제하도록 스토리지 관리 정책 수립.

3. PeopleJob — 채용 플랫폼 리뉴얼 및 데이터/성능 재설계

🎯 기획 목표: 2019년 레거시 채용 플랫폼의 느린 데이터 처리 속도와 파편화된 유저 여정을 재설계. B2B(기업)/B2C(구직자)/Admin 3개 축의 역할 기반 서비스 및 REST API 전체 구조 재정립.

📊 비즈니스 & 성능 성과: k6 부하테스트 시뮬레이션(100 VU · 10만 건 시드) — 데이터 조회 속도 13.8s → 0.1s (-99.3%) 단축 요구사항 명세, 에러율 0% 달성, 전 도메인 유즈케이스 명세 작성

🔗 프로젝트 저장소: Backend PRD  |  Frontend PRD

🛠 핵심 제품 기능 (3축 역할 기반 기획)

  • 구직자(B2C): 회원가입/인증, 이력서 작성(리치텍스트 편집기), 채용공고 탐색/필터링, 1-Click 지원 및 지원 현황 관리
  • 기업(B2B): 공고 생애주기 관리(DRAFT → PUBLISHED → EXPIRED), 지원자 관리 퍼널, 5단계 공고 상단 노출 광고 결제 플로우
  • 관리자(Admin): 회원 및 공고 일괄 관리, 데이터 추출(Excel 내보내기), 플랫폼 통계 대시보드, 알림/팝업 운영

👨‍💻 PM 및 데이터 기획 역할

  • 도메인 통합 REST API 및 데이터 권한 모델(RBAC) 기획
    19개 컨트롤러 영역의 데이터 흐름 설계. 구직자/기업/관리자 간 권한 침범 취약점을 분석하고 토큰 기반 검증 요구사항을 명세하여 보안 리스크 차단.
  • 서비스 SLA 및 성능 지표 개선 리딩 (SLA Optimization)
    대용량 공고 조회 시 발생하는 병목 현상을 해결하기 위해 캐시(TTL 10분) 및 비동기 처리 요구사항을 명세. k6 부하 테스트 시나리오를 직접 설계하여 p95 응답시간을 13.8초에서 0.1초로 99.3% 개선.
  • 수익화 모델(BM) 및 결제 UX 퍼널 기획
    5단계 공고 상품 결제 전환 퍼널(효과 안내 → 공고 선택 → 상품 선택 → 기간 선택 → 영수증) 화면 및 상태값 변화 흐름 정의.
  • 데이터 정합성 및 자동화 라이프사이클 설계
    공고 내용 변경 시 기존 캐시 데이터를 즉시 무효화하는 라이프사이클 명세를 기획하여 정보 불일치 가능성을 0%로 통제. 공고 만료 자동화 스케줄러 기획.

1. LLM 응답 불확실성으로 인한 앱 크래시 문제 해결

문제 정의: AI 추천 기능 이용 시, LLM 응답이 비정형 마크다운이나 부연 설명 문장으로 반환되어 시스템 파싱 오류 및 앱 강제 종료 발생.

기획적 해결: AI 응답 규격을 파싱 전 정제하는 전처리 정책 수립, 파싱 예외 발생 시 최대 2회 자동 재시도하는 Fallback 정책 적용. 실패 시 사용자 안내 팝업을 노출하여 UX 단절 방지.

2. API 과호출(HTTP 429)에 따른 데이터 유실 및 비용 급증 해소

문제 정의: 추천 장소(10~15개)의 좌표를 구하기 위해 외부 지도 API를 동시에 호출하면서 요청 제한(429 Too Many Requests) 오류 발생.

기획적 해결: 병렬 호출 방식을 순차 호출 및 시간 차 지연 정책으로 전환하여 API 오류 발생률을 100%에서 0%로 완벽 해소하고 추천 플로우 안정화.

3. 검색어 입력 시 서버 과부하 및 비용 증가 문제 차단

문제 정의: 유저가 검색어를 한 글자 입력할 때마다 실시간 쿼리가 실행되어 불필요한 데이터 읽기 비용 발생 및 화면 깜빡임 현상 유발.

기획적 해결: 300ms 디바운싱 정책을 적용하여 입력 완료 시점에만 데이터 조회가 실행되도록 개선. 데이터 호출 횟수 약 75% 절감 및 매끄러운 검색 UX 제공.

🌐 ShareLingo (안전 정책 & 동시성 문제 해결)

1. 안전성 AI 로딩 지연으로 인한 첫 이미지 필터링 누락 방지

문제 정의: 앱 실행 직후 이미지 선택 시, 안전 검사 AI 모델 초기화가 완료되지 않아 부적절한 이미지(인물 사진)가 필터링 없이 업로드되는 허점 발견.

기획적 해결: 앱 구동 시 모델 사전 로딩 정책 수립. 준비 상태가 확인되기 전까지 유저의 이미지 접근을 차단하는 인터랙티브 로딩 플로우를 설계하여 위반 이미지 누락 건수 0건 달성.

2. 동시 유저 데이터 조작 시 투표 카운트 덮어쓰기 오류 방지

문제 정의: 다수 유저가 동시에 투표 참여 시, 기존 데이터가 나중 값으로 덮어씌워져 집계 수치가 누락되는 현상 발생.

기획적 해결: 원자적 증감(Transaction) 처리 및 중복 투표 유저 ID 검증 요구사항을 명세하여 데이터 정합성 100% 보장.

💼 PeopleJob (성능 & 시스템 문제 해결)

1. 데이터 캐시 적용 시 최신 공고 반영 지연 문제 해결

문제 정의: 조회 성능을 위해 채용공고를 캐싱했으나, 공고 수정/상태 변경 직후에도 유저에게 구 데이터가 지속 노출되는 정합성 문제 발생.

기획적 해결: CUD(생성·수정·삭제) 이벤트 발생 시 관련 캐시를 즉시 무효화(Cache Eviction)하는 라이프사이클 정책을 작성하여 최신 데이터 정합성 100% 및 고성능 유지를 동시에 달성.

2. 토큰 만료 시 무한 재시도 오류 및 유저 갇힘 현상 방지

문제 정의: 인증 토큰 만료 시 재발급 과정에서 오류가 발생하면 무한 재시도 루프에 빠져 유저 화면이 멈추는 현상 발생.

기획적 해결: 인증 재시도 횟수를 1회로 제한하고, 토큰 만료 시 안전하게 세션을 정돈한 후 로그인 화면으로 유도하는 예외 처리 플로우 설계.
